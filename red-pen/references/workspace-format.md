# red-pen 工作区与脚本契约

这份文件是**文档、`scripts/redpen.py`、`scripts/selftest.py` 三方共享的约定**。改了这里的任何一条数字或键名，同一个 commit 里必须同步改脚本与自测；反之脚本行为变了，也要回头改这份文件。不允许「先改脚本，文档以后补」。

全部路径都相对**工作区根目录**——就是 `drafts/` 的父目录，也就是 `--root` 指的那个目录（默认当前目录）。

## 1. 目录布局

```
drafts/<slug>/
  draft.md            用户的稿子，init 时落进来；脚本此后一个字都不改
                      后缀跟着来源走：.md / .html / .txt（.docx 抽成文字后存 .txt；标准输入存 draft.txt）
  brief.json          给谁看 / 要达到什么 / 最怕什么
  inbox/
    marks.json        Agent 唯一可写的文件：这一轮批注的原始提交
  marks.json          过了闸门之后由脚本写出的记录（真相在这里，不在 inbox）
  review.html         红笔页，由 marks.json 渲染，逐字节可复算
  history/
    v1/               上一版的 draft.* / marks.json / review.html（init 收新稿时归档）
    v2/
    review-0001.json  每次 review 通过时的留档，编号只增
    review-0002.json
```

stdin 与文件路径走同一条收稿通道，使用 `init <slug> --from -`；标准输入没有文件后缀，统一落成 `draft.txt`。

`<slug>` 只能是小写字母、数字与连字符，不超过 64 位，且必须以字母或数字开头。

`draft.*` 在一个工作区里只有一份。`init` 先比内容：收稿层抽出的正文与目标后缀都与当前版相同，就不归档、不建新版本，原地退出 0；普通原样重收不写任何文件。显式 `--lang` 仍然生效，只有语言需要更改或 brief 缺失时才写 `brief.json`；语言更改会使旧批注的 `context_hash` 失效，须重跑 `context` → 写批注 → `review`，原有产物仍留在原地。

后缀也必须相同：若只比正文就省略归档、再按新后缀写文件，会同时留下两个 `draft.*`，而取稿路径只取排序第一个。正文或目标后缀改变才算新一版，先把当前的 `draft.*`、`marks.json`、`review.html` 整个搬进 `history/v<N>/`，再写新稿——**历史只增不改**，`history/v<N>/` 已经存在就直接报错，不覆盖。当前是第几版 = 已归档的 `v*` 目录数 + 1。

`history/review-*.json` 不随版本归档移动，它记的是「这个工作区一共通过了多少轮批注」，跨版本连续编号。

## 2. `brief.json`

```json
{
  "audience": "有小学生的家长，多数在通勤路上用手机读",
  "purpose": "让人读完能自己列出选班的判断顺序，不必再来问",
  "worries": ["写成了推销", "只有态度没有可照做的步骤"],
  "lang": "zh"
}
```

- 四个键，一个都不能多：多出来的键直接报错退出 2。
- `audience` / `purpose`：字符串，写完会被 strip。
- `worries`：字符串数组，空串会被丢掉；没有就写 `[]`。
- `lang`：只能是 `zh` 或 `en`，指的是**批语的语言**，不是稿子的语言。
- 由 `brief set <slug> --from <文件>` 写入。`init` 时如果还没有这个文件，脚本会先放一份模板：前三个键空着，`lang` 记 `zh` 或 `--lang` 给的值。
- **`brief` 进 `context_hash`**：改过 brief 之后必须重跑 `context`，之前写的批注一律作废。

## 3. `inbox/marks.json`（Agent 写的那一份）

```json
{
  "context_hash": "03422eb4…",
  "marks": [
    {"quote": "问不清楚的先不报",
     "level": "major",
     "note": "这是全篇最能直接照做的一句，却被塞在长句尾巴上。",
     "fix": "拎出来单独成段，前面加一句「这条最省钱」。"}
  ]
}
```

顶层只认 `context_hash` 与 `marks` 两个键，多一个就整份拒收。单条批注只认四个键：

| 键 | 必填 | 说明 |
|---|---|---|
| `quote` | 是 | 稿子里的原句，**一字不差地照抄**。脚本靠它把批注钉回原文 |
| `level` | 否 | `major` / `minor` / `remark` 三选一，默认 `remark`；写别的会被改判成 `remark` 并出 WARN |
| `note` | 是 | 批语：这一句出了什么问题 |
| `fix` | 否 | 改法。只针对被引的这一句，不是整段重写 |

没有分数、没有总评、没有条目表——red-pen 不打分。

`quote` 逐字照抄是 Agent 的提交纪律。引擎仍保留规范化与头尾锚定兜底，定位成功不证明引文逐字相同；交稿前仍须用这一轮 `draft_text` 核对来源。

`context_hash` 从 `context <slug>` 的输出里原样取，不要自己算、不要手抄。它等于对 `{"draft_text": …, "brief": …}` 做键排序、无空格、中文不转义的 JSON 序列化后取 SHA-256；`draft_text` 是脚本从稿子抽出来的那份纯文本（第 6 节）。**没跑 `context` 就写不出对得上的哈希**，这是第一道闸门存在的意义。

## 4. 闸门（`review` 与 `check` 走的是同一条通道）

| # | 闸门 | 不过的后果 |
|---|---|---|
| 1 | `context_hash` 等于当前重算值 | 拒收 |
| 2 | 形状：条数、引文、批语、改法（见下） | 拒收 |
| 3 | 锚定率 ≥ 0.7 | 拒收，并逐条列出钉不住的引文 |
| 4 | 两条引文规范化后相同、或两条批语规范化后相同 | 拒收 |
| 5 | 已锚定的引文全落在稿子开头 20% 篇幅里，**且稿子至少 3 块** | WARN，不拦 |
| 6 | `fix` 合计字数 > 稿子字数的一半（**短稿至少 60 字**） | 拒收 |

另有两条只提醒不拦的：`brief` 里 `audience` 与 `purpose` 都还空着；某条 `level` 不在白名单里被改判成 `remark`。

第 2 条的形状闸展开：

- `marks` 是数组，条数在 **1–30** 之间。
- `quote` strip 后非空，字数 **≤ 200**，且**原串 ≤ 400 字符**——两条都要过。
- `note` strip 后字数 **≥ 6**。
- `fix` 这个键一旦出现：strip 后不能是空串；规范化后不能与 `quote` 相同；字数**不超过预算**——预算 = 引文字数 × 3，**最少 20 字、最多 40 字**。不想给改法就把这个键去掉，不要留空串。

单条与合计预算只约束长度，不能保证识别所有整段或整篇短稿重写。即使所有闸门通过，仍须遵守只给逐句批注、不代笔的纪律；不许把几条 `fix` 拼成完整新稿交付。

形状闸没过就不进锚定——拿一份自己都不认的批注去改原文没有意义。所以 `review` 失败时看到的永远是「先把形状改对」，锚定率要等形状全过了才报。

## 5. 怎么数：一把主尺，另加三处例外

1. **主尺 `unit_len`。** 汉字、假名、谚文逐字计，连着的字母或数字算一个，标点与空白不计。五处用的都是它：引文上限（200）、批语下限（6）、单条改法预算（引文字数 × 3，最少 20、最多 40）、改法合计预算（稿子字数的一半，短稿至少 60）、`init` 打印的正文字数。分母那一侧同样按它数：改法合计闸的分母是**稿子的纯文本**（第 6 节，不是文件字节数，也不是原始 HTML 的长度）数出来的字数。这把尺对规范化不敏感——折叠空白、归一引号都不改变它数出来的值。

2. **例外一：引文另有一条 400 的原串字符硬顶。** 这一条数的是 strip 之后的**字符数**，标点、空格全算。它接的是「整段英文按词数不满 200 字，却已经抄了一大片」那种绕法：字数闸与字符硬顶都过了才算过。

3. **例外二：覆盖闸算的是消毒后 HTML 里的起始偏移。** 它比较的是每条已锚定批注的起始偏移与 HTML 总长度的比值（0.2），不是纯文本偏移。标签密集的稿子（例如每段都套着一层容器）里，同一句话的偏移会比它在正文里的位置显得靠后，这条提醒因此偏保守——它只是 WARN，看一眼后半段确实批过就不用管。

4. **例外三：覆盖闸的前提是块数 ≥ 3。** 分不出三块的稿子不提醒——「前 20%」在一段话的公告上没有意义。块数按**块边界**数（段落、列表项、表格行、标题之间），**不是数换行符**：一段里连着敲了几个换行的公告仍然算一块。反过来这个量会偏少：HTML 稿里某一块的文字本身以换行结尾时，那处真实的段落边界与块内软换行分不开，脚本把两段当成一块（第 6 节末尾那条边界写着为什么）。偏少只往沉默那一侧偏——该响的提醒可能不响，不会误报。

`fix` 与 `quote` 是否相同，用的是**规范化之后的等值比较**，不是长度：规范化 = 空白折叠成单个空格并去首尾、不换行空格与全角空格变普通空格、弯引号（`‘’“”«»` 等）归到直引号、各种破折号（`–—−‐‑`）归到 `-`；中文全角标点 `，。！？：；（）` 原样保留。所以只把直引号换成弯引号、或者多打一个空格，规范化之后还是同一句，照样算「fix 与引文相同」被拒。

## 6. 稿子怎么被读出来

`init` 先做准入、再解码，读完的正文写进 `draft.*`。格式后缀忽略大小写：

- `.txt` → `draft.txt`；`.md` / `.markdown` → `draft.md`。**Markdown 不解析**，`##` 与 `**` 仍是普通字符。
- `.html` / `.htm` → `draft.html`。
- `.docx` → 用 zipfile + XML 读 `word/document.xml`，抽成纯文本存 `draft.txt`。它本来是 ZIP，**不过内容嗅探**，假 docx 由 ZIP／XML 读取报错拒收。
- 拒收 `.pdf`、`.doc`、`.rtf`、`.odt`、`.pages`、`.epub`；表格 `.xlsx`、`.xls`、`.csv`、`.numbers`；演示 `.pptx`、`.ppt`、`.key`；图片 `.png`、`.jpg`、`.jpeg`、`.gif`、`.bmp`、`.tif`、`.tiff`、`.webp`、`.svg`、`.heic`、`.ico`；压缩包 `.zip`、`.rar`、`.7z`、`.gz`、`.gzip`、`.tar`、`.bz2`、`.xz`、`.tgz`。每类说明如何导出正文再来；后缀命中就拒收，即使内容可解码。
- 其它后缀或无后缀、且没有内容拒收证据的文件，收为 `draft.txt` 并提醒「这个后缀我不认得，按纯文本读的。读出来不是你的正文就换个格式再来。」标准输入不打未知后缀提示。

非 docx **先按内容拒收，再按后缀拒收**。内容判据是开头魔数 `%PDF-`、`{\rtf`、`PK\x03\x04`、`\xd0\xcf\x11\xe0`、`\x89PNG`、`\xff\xd8\xff`、`GIF8`、`%!PS`、`\x1f\x8b`、`\x7fELF`，以及前 `SNIFF_BYTES = 8192` 字节中的 NUL。**NUL 判据必须先检查 BOM**：只有 UTF-16／UTF-32 BOM 可豁免 NUL 判据，因为这些编码正文正常含零字节，交给相应解码器验证；UTF-8 BOM 不豁免 NUL。**嗅探只用来拒收，不用来放行**；`anchor.py` 里的 `_HTML_MARKER` 是**路由**嗅探（决定走 HTML 消毒还是包成段落），不是**准入**嗅探，不能拿它绕过后缀拒收。

原稿解码按三档：①有 BOM 就按标记严格解码，UTF-32 必须先于 UTF-16 判定，UTF-8 BOM 用 `utf-8-sig`，UTF-16／UTF-32 各用对应解码器；②无 BOM 时严格 UTF-8；③失败后只猜一次 GB18030（也覆盖 GBK）。带 BOM 但编码损坏直接拒收，不改猜别的。全部解码后统一 CRLF／CR 为 LF，保持原先文本模式的换行行为。UTF-8 不打编码提示；BOM 说明依据文件头；GB18030 明说「猜的」，原样打印正文开头两行让用户核对，乱码就停下，不接着批。**此兜底只用于原稿**；`brief.json`、`inbox/marks.json` 与工作区文件读取仍为严格 UTF-8，允许 UTF-8 BOM，不猜旧编码。

DOCX 表格按行读出来，同一行的单元格用制表符相连，整行可以整句引；一个单元格内多个段落用空格相连，空单元格保留列位置；行与行之间是块边界，跨行引不了。行或单元格外包的内容控件透明穿过，仍按原顺序取行、取格；到达目标行／格就停止向下寻找同级节点。嵌套表格的文字归所在的外层单元格，按段落用空格相连，不重复算作外层的行或列，也不保留内层表格的行列边界。文本框沿正文位置读一次，跳过 `mc:Fallback` 重复内容。脚本按实际出现的表格、文本框、图片结构、修订分别提示：图片本身与图片里的字读不到，不做文字识别；**普通文字段落里的图注仍会读到**。只读取正文文字节点，通常含插入文字而不含删除文字节点，不替用户接受／拒绝修订，也不读 Word 批注。整篇只有图片、没有文字的稿子拒收。

升级说明：表格抽取改变时，DOCX 正文与哈希会变化，旧批注须重做；纯段落 DOCX 可能逐字不变，不能断言所有 DOCX 哈希都变。**用 docx 或非 UTF-8 收过的稿子，升级后请重跑一次 `init` 收成新版本，再 `context` → 重写批注 → `review`。** 若抽取正文与目标后缀未变，`init` 会按第 1 节原样重收，不强行升版；随后照常重跑上下文与批注流程。

批注要钉回原文，靠的是脚本抽出来的**纯文本**（`context` 输出里的 `draft_text`）：非 HTML 的输入先按空行分段包成段落；段落、列表项、表格行、标题、换行这些块边界在纯文本里各占一个换行符。**块边界与块内软换行在 `draft_text` 里都写成一个换行符，脚本靠位置映射分辨**（块边界是零宽区间，软换行不是），引文不能跨块——横跨两个段落的句子锚不上，只能引其中一段。软换行指的是**纯文本、Markdown 与 docx 稿里段落内部的那种换行**，它不算跨块，一段用软换行写的编号列表可以整段引；**HTML 稿里的 `<br>` 是块边界**，跨 `<br>` 的引文锚不上。

反过来那一向**不恒成立，别当它是**：HTML 稿里若某一块的文字本身以换行结尾（缩进美化过的稿子最常见，`<p>甲␊</p><p>乙</p>` 就是），脚本在那处不再补零宽分隔符，这处真实的段落边界就与块内软换行分不开——`draft_text` 看起来一模一样，而脚本会把两段当成一块，引文也就跨得过去。所以「块数」这个量在这类稿子上偏少，靠块数决定要不要提醒的地方要把这条算进去。想避开它，把稿子存成 `.txt` / `.md` 收进来即可。

HTML 稿子进引擎前先过白名单消毒：`script` / `style` / `iframe` 这类没有正文语义的标签**连内容一起丢**，其余标签脱掉外壳、文字保留。一条边界要知道：这类丢弃标签若**没有闭合**，按「到文件末尾自动闭合」处理——它之后的所有内容都会被当作该标签的内容一并丢掉（与浏览器的解析行为一致）。`draft_text` 突然比稿子短一截时，先检查稿子里有没有未闭合的 `<script>` / `<style>` / `<iframe>`。

## 7. `marks.json`（过了闸门之后脚本写的那一份）

```json
{
  "slug": "newsletter-01",
  "version": 1,
  "at": "2026-08-31T16:31:01",
  "draft_file": "draft.md",
  "draft_sha256": "…",
  "context_hash": "…",
  "anchored_ratio": 0.8571,
  "level_counts": {"major": 2, "minor": 3, "remark": 2},
  "marks": [ … ]
}
```

`marks[]` 里每条固定带这些键（`fix` / `start` / `end` 三个视情况出现）：

| 键 | 说明 |
|---|---|
| `id` | 从 1 起的编号，与红笔页上的编号、正文里的下划线一一对应 |
| `quote` / `level` / `note` / `fix` | 原样留着，`level` 已经过白名单兜底 |
| `anchored` | 是否钉住了原文 |
| `partial` | 只靠头（或尾）对上的，区间按引文长度推出来，仅供参考 |
| `start` / `end` | 在消毒后 HTML 里的区间，只有 `anchored` 为真时才有 |
| `level_fixed` | 提交的等级不在白名单里，已被改判成 `remark` |
| `dropped_overlap` | 与已保留批注的区间相交，脚本留了起点靠前的那条（同起点取长），这条降成未锚定 |

**顺序不是提交顺序**：钉住的条目按它在原文里出现的先后排在前面，钉不住的排在后面，`id` 按这个顺序重新编。所以「第 3 条」指的是红笔页上的第 3 条。

**计数一律以这份 JSON 的 `marks` 为准。** 一条批注在红笔页的正文里可能画成好几段下划线——引文横跨行内标签时，每个文本片段各包一层，它们共用同一个编号。数 HTML 里的下划线会数多。

`anchored_ratio` = 钉住的条数 ÷ 总条数，保留四位小数。`level_counts` 三个等级都在，没有的记 0。

## 8. `review.html`

由 `marks.json` 加稿子渲染出来的单页：左栏是原文，钉住的句子带下划线；右栏按编号列条目，钉不住的单列一节「未能定位」。自包含，无外链，深浅色都能看，可以直接截图。

**不能手改。** `check` 会拿 `marks.json` 重新渲染一遍再与磁盘上的逐字节比对，改一个字都会被报出来。要改内容就改 `inbox/marks.json` 再跑一次 `review`。

## 9. `export` 的形状

`export <slug>` 只把计数打到标准输出，**不含任何正文**——引文、批语、改法一个字都不导出：

```json
{
  "anchored_ratio": 0.8571,
  "context_hash": "…",
  "level_counts": {"major": 2, "minor": 3, "remark": 2},
  "marks_count": 7,
  "slug": "newsletter-01",
  "versions": 1
}
```

## 10. `check` 复核哪些事

`check <slug|目录>` 是离线复核，发布前靠它：

1. 稿子还在，`draft_sha256` 与现在的 `draft.*` 对得上（稿子改过就得重跑 `context` 与 `review`）。
2. `marks.json` 记的版本号等于工作区当前版本。
3. 拿 `marks.json` 里的 `context_hash` 与四个契约键**重跑一遍全部闸门**（第 4 节）。
4. 重新算锚定率与等级分布，与记录里的对得上。
5. `review.html` 在，且与重新渲染的逐字节相同。
6. `history/` 里有留档（没有只出 WARN）。

有 ERROR 退出 1，没有退出 0。`examples/drafts/` 下的示例工作区必须 0 ERROR，`scripts/selftest.py` 会替你跑一遍。

## 11. 退出码

| 码 | 含义 |
|---|---|
| 0 | 通过 |
| 1 | 闸门没过（`review` 拒收、`check` 有 ERROR）——改 `inbox/marks.json`，不要改稿子 |
| 2 | 用法或输入格式错误（找不到文件、JSON 坏了、编码读不出、格式收不了、slug 不合法、brief 多了键） |


## 12. `init` 会打印哪些提示

第一次收稿的三行形状如下：

```text
建好工作区：<slug>（第 N 版）→ drafts/<slug>
稿子：draft.<后缀> · 正文 N 字（汉字按字、英文按词，标点不算）[ · 批语语言 <lang>]
收进来：<源文件名> → draft.<后缀>
```

收到新稿时，第一行改成「收到新一版稿子：<slug>（第 N 版），上一版已归入 history/v<上一版号>。」。源文件名只给 basename，不带目录；标准输入的标签为「（标准输入）」。三行之后打印下一步；收稿层附加提示与长稿提醒也统一放在收稿行之后。

规模短语由 `_size_phrase` 统一生成，口径指回第 5 节的主尺 `unit_len`；英文稿也用这把尺，单位仍写「字」，全库没有第二套字数单位。方括号只是这里的可选项标记，实际不打印：显式给了 `--lang`，或收稿前工作区已有 `brief.json`，才追加「 · 批语语言 <lang>」。第一次收稿没给 `--lang` 就不打印这半句，`init` 不会替用户猜批语语言。

`DRAFT_WARN_CHARS = 50000`，仅当收稿层抽出的正文满足 `len(text) >= DRAFT_WARN_CHARS` 时提醒。这里按抽取文本的字符数判定，不是第 5 节闸门的字数口径，也不是新闸门；HTML 在这里按收稿层读出的文本字符数计算。提醒为「这份稿子很长：<规模短语> —— 一轮最多 30 条批注，红笔页会很难读，建议先切成一节一节地批。」，规模短语与摘要一样从纯文本调用 `_size_phrase`。随后提示「如果你也装了段级评审那个技能，可以先用它定位最弱的一段，再把那一段单独送进来。」。长稿输出中「正文」出现两次，分别在摘要和提醒里；普通短稿只有一次。

原样重收改为说明「稿子和第 N 版逐字相同，没有收成新版本 —— marks.json 与 review.html 都留在原地」，再打印 `context` → 写批注 → `review` 的下一步，并提醒核对 `--from` 是否指向新文件。若显式改了批语语言，会另说清 brief 已变、旧批注作废。原样重收也打印收稿提示，编码猜测与 DOCX 边界不会因为正文未变而省略。

**这些是提示不是闸门**，不改变任何退出码。
