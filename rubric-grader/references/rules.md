# 批改纪律：怎样让一份判定「核得住」

评分标准是老师的，判定由模型给。这份文件只管一件事：**怎么让每一条判定都能被机器核一遍**。下面每一条都对应一种真实的白给分方式，脚本会逐条判定；判定不过就不落盘，退出 1，让 Agent 改评分结果重来。

先记住三句话：

1. **判定要有作答里的原句撑着。** 说不出他哪一句写到了，就不能说这一条命中。
2. **开批之前先证明自己批得准。** 满分范例批不出满分、残缺版还能批出命中，这一轮的分数没有意义。
3. **假作答必须 0 分。** 空白、题面贴回、无关段落——三份里任何一份拿到分，整批分数都不可信。

## 一、闸门八条

### 1. 上下文哈希：没跑 `context` 就不许写结果

评分结果里的 `context_hash` 必须等于脚本当场重算的值。这个哈希取自题干、评分标准、条目表、作答四样材料的纯文本，外加 `job.json` 里的满分与语言（`max` / `lang`）。它挡两件事：

- **凭印象批。** 没跑 `context` 就没有这一串，手编一个当场被拒。
- **拿旧结果冒充新的。** 老师改了一个错字、换了一份作答、调了条目表，哈希就变了，之前批的自动过期。

哈希对不上时不要去猜哪里变了，重跑一次 `context`，照新的上下文包重批。

### 2. 形状与分数：五个顶层键，分数与条目判定一致

顶层只接受 `context_hash` / `points` / `summary` / `criteria` / `marks`，**多一个键也拒收**。这一条防的是「顺手多写几个自己觉得有用的字段」——多出来的字段没人核，等于凭空多出一套没有依据的结论。

`points` 必须是整数、落在 0 到满分之间。条目表带分值时，它必须精确等于：命中拿该条满分、部分命中拿一半向下取整、未命中拿 0 的合计。这条闸门挡的是「条目都判了部分命中，总分却给满」这种最常见的宽松打分——判定和分数是同一件事的两种写法，对不上就说明其中一个是编的。

条目表不带分值时算不出合计，但守一条底线：**条目全部未命中却给了分，拒收**——这个分数没有任何条目撑着。

### 3. 条目一一对应，引文必须钉得回原文

`criteria` 与条目表逐条对应，不多、不少、不重复。少一条是漏批，多一条是自己加戏，两种都拒收。

判命中或部分命中，就必须给出作答里的一句原文当证据，而且这句话要能被引擎钉回原文。**引文钉不回去，这一条自动降为未命中**，并记下 `evidence_unanchored`。降完之后：

- 分数没变（这条本来就是 0 分或不影响合计）：放行，记一条 WARN，让老师知道证据没落实。
- 分数变了：**整份退回重批**。脚本不替你把分数改小——改小了就是脚本在替模型下判定，那不是它该做的事。
- **条目表不带分值：引文一钉不回去就整份退回。** 脚本算不出「降级该扣多少」，宽容不到「反正也算不出扣几分」的地步；换一句真的在作答里的引文，或者如实判未命中。

引文一律**从作答里原样复制**。不要顺手改标点、不要把两段话拼成一句、不要「大意是这样」。引擎会容忍空白折叠、弯引号与破折号的写法差异，也会做头尾锚定，但跨段落的拼接一律不认——那种引文钉上去会吞掉标签，宁可不锚。

判未命中时引文可以留空。这不是偷懒的口子：未命中本来就是「作答里找不到」，硬找一句话来引反而是在编。

### 4. 批注：有上限、有下限、不许重复

- **条数上限** `max_notes`，默认 12，老师可以在 `job.json` 里改。上限不是为了省事，是因为一份作答上贴二十条批注，学生一条都不会看。
- **每条要有引文，批语至少 6 个字。** 「好」「不对」不是批语。
- **锚定率下限** `min_anchored`，默认 0.7，老师可改。一份作答里超过三成的引文钉不回原文，说明这一轮在凭印象引用，整份拒收。
- **两条批语一字不差就拒收。** 同一句话说两遍，第二遍是凑数。

锚不上的批注不会被丢掉，它照样进结果（`anchored: false`），在判题卡右栏「未定位」一节单列。**脚本不擅自把它摆到原文的某个位置上**——摆错地方比不摆更糟。交付时要提醒老师人工看一眼这一节。

批注等级只有 `major` / `minor` / `remark` 三档。白名单外的值会被改成 `remark` 并记一条 WARN，绝不原样写进 HTML 属性。

### 5. 总评：60–200 字，不逐题复述

总评是**对这一份作答的整体评价**：他答到了什么程度、卡在哪里、下一步改什么。

- 少于 60 字（英文 60 词）是敷衍，多于 200 字学生不会读完。
- **不许出现「第 N 题」式的逐题复述。** 把评分标准逐条抄一遍再说一句「以上」，是在填格子不是在批改；老师要看标准会自己去看 `rubric.md`。

### 6. 雷同闸：一份评语贴不了全班

同一批次里，两份结果的总评一字不差，或者批语集合的重合度（Jaccard）达到 0.8，后一份拒收。

批得越多越容易滑向同一套说辞，这条闸门就是拦这个的。它对**学生**生效，对抗基线之间不比——三份假作答的评语本来就该长得像。

### 7. 空心批注（WARN）

一份作答里所有引文都不超过 6 个字，而且每条批语与作答没有任何 3 字重合——这通常意味着批的时候没有真读作答，只是照着评分标准写了几句通用的话。

这一条只提醒不拦截：短引文有时是合理的（一个错的术语、一处标点）。看到这条 WARN 就回头确认一次，确认没问题就照常交付。

### 8. 校准失效：材料改过，之前批的都不算

`rubric.md`、`question.md`、`oracle/full.md`、`oracle/broken.md`、`oracle/broken.json`——**五份材料**的哈希记在盖章里，任一改动盖章立刻作废。

作废之后：`grade` 拒绝开批，`summary` 与 `export` 拒绝生成，`check` 报盖章作废。已有结果标不标过期（stale）看改的是什么：改 `rubric.md` / `question.md`（或 `job.json` 里的 `max` / `lang`、条目表）会让每份结果的上下文哈希对不上，逐份标过期；只改 `oracle/*` 三份时结果的哈希没变、本身不标过期，但盖章作废同样挡住 `grade` / `summary` / `export`。处理方式只有一种：重跑 `oracle check` 盖新章，过期的再逐份重跑 `grade`。

不要因为「只改了一个错别字」就想绕过去。改一个字也可能让某条判定从命中变成未命中，何况老师改的往往不是错别字。

## 二、开批前的校准：`oracle check`

模型批得准不准，不能靠它自己说。校准用两份材料，都由老师说了算：

- **满分范例** `oracle/full.md`：一份能拿满分的作答。老师手上没有现成的，Agent 可以照着评分标准起草一份，但必须**明说这是草稿、请老师改**，改完才落盘。草稿没经老师过目就拿去校准，等于模型自己出题自己判。
- **残缺版** `oracle/broken.md`：把满分范例里某一条对应的内容整段删掉。**删哪一条由老师指定**——他指定的那一条，就是他最怕批漏的那一条。删掉的条目名写进 `oracle/broken.json` 的 `missing`。

裁决很简单：

| 材料 | 必须满足 | 不满足说明 |
|---|---|---|
| 满分范例 | 分数等于满分，**每一条都命中** | 批得太紧，或者条目表跟评分标准对不上 |
| 残缺版 | 分数低于满分，且 `missing` 里每条都判未命中或部分命中 | 在无中生有：作答里没有的东西也能批出命中 |

两份都过才盖章，盖章之后才准开批。**没过就停下**——改你写的那两份评分结果，或者请老师改范例。不要去改残缺版删掉的内容让它变得「好判一点」，那是老师定的东西。

## 三、基线裁决：假作答必须 0 分

每一批作答里都要放三份对抗作答，文件名以 `base-` 开头：

| 文件 | 内容 | 它验证的事 |
|---|---|---|
| `base-empty.md` | 空白 | 不会因为「格式规范」「态度端正」这种理由给分 |
| `base-echo.md` | 把题面原样贴回来 | 不会把题面里的关键词当成作答里的定义 |
| `base-noise.md` | 一段与题目无关的文字 | 不会按篇幅给分 |

**这三份必须批出 0 分，且每一条都判未命中。** 脚本对文件名以 `base-` 开头的作答强制这条裁决，`grade` 与离线复核都会查。

批出任何一分，都不是「这份基线设计得不好」，而是**这一轮的批改在白给分**——同一套判断标准用在真作答上，给出的分数同样不可信。这时候要做的是回头看：是条目判据太宽，还是总评的语气带着分数走。

三份基线不计入全班汇总的平均分与条目统计，也不参与雷同闸的比对。

## 四、评分标准怎么写才可批

老师给的评分标准是散文、是表格、是一段微信消息，都没关系；`rubric.md` 逐字保存它，脚本不解析。要做的是把它整理成一张表，**念给老师听、请他确认**，每条三样东西：

| 条目名 | 分值 | 一句判据 |
|---|---|---|
| 定义准确 | 2 | 说出机会成本是放弃的选项里价值最高的那一个；只说「放弃的东西」给 1 分 |
| 例子贴切 | 2 | 举了具体例子，并点明这个例子里被放弃的最优选择 |
| 表述清楚 | 1 | 句子通顺、结论明确，通篇同义反复的不给分 |

四条要求：

1. **一个条目只问一件事。** 「定义准确」和「例子贴切」是两条；「内容完整」不是一条，它没法指着作答说是或不是。
2. **判据要能指着作答说是或不是。** 写不出这样一句话，说明这一条还没想清楚，先问老师，不要自己替他定。判据本身不进条目表（`criteria.json` 只收 `name` 与 `points`），它是给你写评分结果时用的备忘，原文在 `rubric.md` 里。
3. **条目名互不重叠、互不包含。** 重叠的条目会让同一句引文被引两次，也会让老师看汇总时分不清到底是哪一条没答出来。
4. **建议每条都标分值，合计等于满分。** 标了分值，脚本才能核第 2 条闸门。**不标分值时，脚本能拦的只剩三条**：命中的引文钉不回原文（整份退回）、条目全部未命中却给了分（拒收）、对抗作答给了分。中间那一大类「条目都判部分命中、分数却给满」的错法，不标分值一律拦不住——这是要跟老师讲清楚的取舍。

条目分值合计与满分对不上时，`rubric set` 退出 1 并**保留旧表**，不会写一半进去。

## 五、几条不写进闸门、但一样重要的话

- **批语是对着那一句话说的。** 不要把评分标准抄进批语里；学生看到的是自己的句子旁边多了一行字，那行字要告诉他这一句为什么不够，而不是复述规则。
- **不要替学生改写答案。** 指出问题、给方向，把改写留给他自己；判题卡不是范文。
- **分数低的时候更要给出下一步。** 0 分和 2 分的作答最需要一句「先做什么」，不然这次批改对他没有任何用处。
- **闸门没过是常态，不是故障。** 说清楚卡在哪一条、你打算怎么改，然后改评分结果重来。静默重试是最糟的处理方式——老师会以为一次就过了。
- **不要为了让某一份通过而修改脚本。** 闸门是这份 Skill 唯一的价值；改掉闸门之后剩下的只是一个批注渲染器。
